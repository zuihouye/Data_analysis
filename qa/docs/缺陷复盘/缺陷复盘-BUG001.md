## 二、现象（员工视角）

- 操作步骤：
  1. 打开 `/login`
  2. 输入已注册手机号和密码
  3. 点击「登录」
- 实际结果：`POST /login` 返回 **500**（Flask 默认 500 页「服务器开小差了」），无 `Location`、页面不跳转
- 期望结果：返回 **302**，`Location: /customer/list`，跳转后 h1 为「客户管理」，再访问 `/order/list` 返回 200（登录态生效）

## 三、复现与最小化

- 复现概率：必现，且**与账号密码对错无关**（SQL 执行阶段就报错，还没走到密码比对）
- 最小复现条件：`GET /login` 取 csrf token → `POST /login`（手机号 15599544930，任意非空密码即可复现 500）
- 环境：Python 3.14.8 / Flask 3.1.3 / redis 6.4.0 / MySQL 8 / Edge 156.0.4314.50

## 四、定位过程（假设 → 验证 → 结论）

1. **假设 1：账号不存在或已被停用** → 验证：查库 `SELECT * FROM users WHERE phone=15599544930`，手机号存在且 `is_active=1`；而且密码错时正常应返回 401 而不是 500 → **不成立**，账号侧排除。
2. **假设 2：前端没发出请求（浏览器/页面问题）** → 验证：F12 → Network，`POST /login` 已发出且状态码 500 → **不成立**，前端排除。
3. **假设 3：服务端 SQL 有问题** → 验证：看 Flask 控制台 traceback 与后端日志，MySQL 报
   `(1054, "Unknown column 'cusrtomer_id' in 'field list'")`，报错语句正是登录那条 `SELECT ... FROM users`；再对照表结构，`users` 表列名是 `customer_id` → **成立**。
4. **结论**：登录查询的列名拼错了。

## 五、根因

- 直接原因：`views/auth.py` 登录查询写成
  `SELECT id, phone, username, password_hash, role, is_active,cusrtomer_id FROM users ...`，
  `cusrtomer_id` 是拼写错误，真实列名是 `customer_id`。
- 深层原因：手写 SQL 字符串里的列名没有编译期校验；「登录成功」这条路径此前只有手工用例、没有接口自动化，改完代码不跑一遍就发现不了，错误只在运行时暴露。
- 为什么之前没发现：LG-01 是本次演练中第一次真正执行。

## 六、修复

- 修改文件与位置：`views/auth.py` 登录查询，`cusrtomer_id` → `customer_id`（只此一处）
- 修改思路：对齐数据库真实列名，查询逻辑不动
- 是否影响其他功能：仅该查询；但登录态是后续所有功能的前置，需回归登录 + 注册两条路径
- 代码提交：工作区修改，尚未提交（提交后补 commit 号）
