## 二、现象（客户视角）

- 操作步骤：
  1. 打开 `/register`
  2. 手机号填 19900000001
  3. 昵称填 测试客户A
  4. 地区选下拉中的值（如 Mandalay）
  5. 密码填 Test-123456，确认密码填同值
  6. 点「注册」
- 实际结果：
  1. `POST /register` 返回 **500**
  2. 响应无 `Location`，页面不跳转
  3. **但数据库已经生成注册数据**（customers、users 各新增 1 行），再注册同号会返回 409「该手机号已注册」
- 期望结果：
  1. `POST /register` 返回 302（不出现成功提示页）
  2. `Location` 指向 `/product/list`
  3. 页面 h1 为「商品中心」且右上角显示已登录
  4. 同一浏览器访问 `/order/list` 返回 200
  5. customers 表新增 1 行（customer_id 形如 `REG-xxxxxxxxxxxx`）
  6. users 表新增 1 行且 role=0、customer_id 与 customers 新增行一致

## 三、复现与最小化

- 复现概率：必现
- 最小复现条件：新手机号 19900000001 + 昵称「测试客户A」+ 地区 Mandalay + 密码 Test-123456（两次一致）
- 环境：Python 3.14.8 / Flask 3.1.3 / redis 6.4.0 / MySQL 8 / Edge 156.0.4314.50

## 四、定位过程（假设 → 验证 → 结论）

1. **假设 1：前端没提交或被前端校验拦住** → 验证：F12 → Network，`POST /register` 已发出、参数齐全、返回 500 → **不成立**，前端排除。
2. **假设 2：插入数据时撞约束（如手机号重复）** → 验证：看 traceback，异常不在 `INSERT`（没有 IntegrityError / OperationalError），而是在 `_save_login` 里抛 `KeyError: 'customer_id'` → **不成立**。
3. **假设 3：注册成功后的查询列与登录态写入读取的列不一致** → 验证：对照源码，注册成功后那条查询是
   `SELECT id, phone, username, role FROM users WHERE phone = :phone`（**没有 customer_id**），
   而 `_save_login` 里是 `session["customer_id"] = row["customer_id"]` → **成立**。
4. **结论**：注册 INSERT 已提交 → 写登录态时 KeyError → 页面 500，数据留在库里形成脏数据。

## 五、根因

- 直接原因：注册成功后的 SELECT 没取 `customer_id`，`_save_login` 无条件读 `row["customer_id"]` → `KeyError: 'customer_id'`。
- 深层原因：登录态写入与查询列之间没有列存在性判断（隐式契约），只要某条 SELECT 少一列就会 500；且注册成功路径此前没有接口用例覆盖。
- 为什么之前没发现：REG-01 是本次演练中第一次真正执行；自动化只覆盖了登录成功路径。

## 六、修复

- 修改文件与位置：
  1. `views/auth.py` 注册成功后的查询补回 `customer_id`
  2. `views/auth.py::_save_login` 改为列存在性守卫：`session["customer_id"] = row["customer_id"] if "customer_id" in row.keys() else None`（根治：以后再漏选列也不会 500）
- 修改思路：让「读列」与「查列」解耦，不再依赖调用方传进来的行一定带该列
- 是否影响其他功能：`_save_login` 被登录与注册两条路径共用，改后两条都要回归
- 代码提交：工作区修改，尚未提交（提交后补 commit 号）

  ```sql
  SELECT id, customer_id FROM users WHERE phone = '19900000001';

  DELETE FROM customers WHERE customer_id = '<上一步查到的 customer_id>';
  ```

## 八、预防措施

- `_save_login` 只读「判存在」的列（`keys()` 守卫，已落地）；
- 登录 / 注册成功路径各 1 条接口用例，进 CI 门禁；
- 凡改动 `_save_login` 或 users 查询列的改动，提交前必须跑 `pytest qa/api`。
