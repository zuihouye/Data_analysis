## 1. `views/auth.py` 改造（共 7 处）

### 1.0 先理解要改什么

原来的 `auth.py` 只有两个角色（1 普通成员 / 2 管理员），登录只写 `user_id/username/phone/role` 到 session。客户要能下单，需要：

1. 增加角色 0（客户），并让它能被正确显示；
2. 新增 `staff_required`（员工/管理员）和 `customer_required`（仅客户）两个装饰器；
3. session 多存一个 `customer_id` —— 客户下单、查自己订单全靠它；
4. 登录/注册后按角色分流：客户进商品页，员工进客户管理页；
5. 新增客户注册路由（一个事务写 `customers` + `users`）。

**面试点**：为什么 `role` 和 `customer_id` 放 session 而不是每次查库？
→ session 是 Flask 用 `SECRET_KEY` 签名过的 cookie，客户端改不动；每次请求只解密、不查库，省一次 DB 往返。代价是"管理员把你的角色改了，你要重新登录才生效"——这是可接受的权衡（也可以做 role 版本号，但项目规模不需要）。

### 1.5 两个新装饰器 + 登录落地页

放在 `admin_required` 函数后面（第 114 行之后）：

```python
def staff_required(view):
    """员工及以上（role 1/2）。内部已含未登录判断，不需要再叠 @login_required。

    商品维护、订单/客户管理、确认收款都用它。
    想收紧成"只有管理员能改商品"，把对应路由的 @staff_required 换成 @admin_required 即可。
    """
    @wraps(view)
    def wrapper(*args, **kwargs):
        if not session.get("user_id"):
            return redirect(url_for('auth.login', next=_current_target()))
        if session.get("role") not in (1, 2):
            logger.warning('越权访问被拦截（需要员工）: user=%s role=%s %s',
                           session.get('user_id'), session.get('role'), request.path)
            return '需要员工或管理员权限。', 403
        return view(*args, **kwargs)
    return wrapper


def customer_required(view):
    """仅客户（role=0）。下单页用。

    额外要求 session 里有 customer_id：角色是客户却没有客户主数据，
    说明数据不完整（比如手工插了一条 role=0 的 users），宁可 403 也不让它下单。
    """
    @wraps(view)
    def wrapper(*args, **kwargs):
        if not session.get("user_id"):
            return redirect(url_for('auth.login', next=_current_target()))
        if session.get("role") != 0 or not session.get("customer_id"):
            logger.warning('越权访问被拦截（需要客户）: user=%s role=%s %s',
                           session.get('user_id'), session.get('role'), request.path)
            return '该页面仅客户可用。', 403
        return view(*args, **kwargs)
    return wrapper


def _home_page(role):
    """登录/注册后的落地页：客户去商品页，员工去客户管理页。"""
    if role == 0:
        return url_for('order.product_list')
    return url_for('user.customer_list')
```

> **为什么不用 `@login_required` 叠 `@admin_required`**：装饰器从内到外执行，`admin_required` 内部已经处理了未登录（否则未登录的普通请求会先被内层拦截、跳错地方）。保持"每个角色装饰器自己处理未登录"这一条约定，就不会出现双重跳转。

### 1.7 新增注册路由（追加到 `login` 和 `logout` 之间或文件末尾）

```python
# 手机号：11 位、1 开头、第二位 3~9（够用即可；真实项目还要考虑 +86/国际号）
PHONE_RE = re.compile(r'^1[3-9]\d{9}$')


@auth_blue.route('/register', methods=['GET', 'POST'])
def register():
    """客户自助注册：一个事务里同时写 customers（主数据）和 users（登录账号）。

    为什么必须一个事务：
      只写 customers -> 有客户没账号，无法登录；
      只写 users    -> 账号的 customer_id 悬空，下单时外键失败。
      两条 INSERT 放同一个 begin() 里，任一失败整体回滚。
    """
    if session.get('user_id'):
        return redirect(_home_page(session.get('role', 1)))

    if request.method == 'POST':
        phone = (request.form.get('phone') or '').strip()
        username = (request.form.get('username') or '').strip()
        region = (request.form.get('region') or '').strip()
        password = request.form.get('pwd') or ''
        password2 = request.form.get('pwd2') or ''

        if not PHONE_RE.match(phone):
            return render_template('register_t.html', error='请输入 11 位手机号'), 400
        if not username or len(username) > 64:
            return render_template('register_t.html', error='昵称不能为空且不超过 64 字'), 400
        if not region:
            return render_template('register_t.html', error='请填写所在地区'), 400
        if len(password) < 8:
            return render_template('register_t.html', error='密码至少 8 位'), 400
        if password != password2:
            return render_template('register_t.html', error='两次输入的密码不一致'), 400

        customer_id = 'REG-' + uuid.uuid4().hex[:12]   # 与 CSV 的 Customer-xxx 区分开
        try:
            with db.engine.begin() as conn:
                conn.execute(text(
                    'INSERT INTO customers (customer_id, region, cus_status) '
                    'VALUES (:cid, :region, 1)'),
                    {'cid': customer_id, 'region': region})
                conn.execute(text(
                    'INSERT INTO users (phone, username, password_hash, role, customer_id) '
                    'VALUES (:phone, :username, :pwd, 0, :cid)'),
                    {'phone': phone, 'username': username,
                     'pwd': generate_password_hash(password), 'cid': customer_id})
        except IntegrityError:
            # 唯一键冲突 = 手机号已被注册（并发注册也拦得住）
            logger.info('注册失败，手机号已存在: %s', phone)
            return render_template('register_t.html', error='该手机号已注册，请直接登录'), 409

        # 注册成功直接登录，省一次输入
        with db.engine.connect() as conn:
            row = conn.execute(text(
                'SELECT id, phone, username, role, customer_id FROM users '
                'WHERE phone = :phone'), {'phone': phone}).mappings().first()
        _save_login(row)
        logger.info('客户注册成功: user_id=%s customer_id=%s', row['id'], customer_id)
        return redirect(url_for('order.product_list'))

    return render_template('register_t.html')
```

> **面试点 1**：为什么客户注册要写两张表？
> → `customers` 是客户主数据（订单外键、RFM 分析都依赖它），`users` 是登录凭据；上一版项目已经踩过"把密码放 customers，导入一次就被冲掉"的坑，所以两张表必须分开、同一个事务写入。
>
> **面试点 2**：为什么要捕获 `IntegrityError`？
> → 应用层"先查后插"有并发窗口（两个请求同时查到手机号不存在），数据库的 `UNIQUE` 约束是唯一可靠的兜底；捕获后返回友好提示，而不是 500。
>
> **面试点 3**：为什么注册后直接登录？
> → 减少一次输入，且注册场景下"刚证明了自己设置的密码"，自动登录没有安全问题；实现上就是 `_save_login(row)`，与普通登录共用同一段逻辑。

## 2. 新增 `utils/order_ops.py`（全文）

> 新建文件。它只做业务规则和数据库事务，**不 import Flask** —— 这样业务函数可以单测、可以被 JSON API 和页面表单同时复用。

```python
"""订单业务操作：下单、改数量、取消、确认收款。

分层：
    本模块 = 业务规则 + 数据库事务（不依赖 Flask）
    views 层 = 解析请求、权限、flash 提示、重定向

状态机（与 schema.sql 注释、1/2/3 对应）：
    1 已下单/待付款  --确认收款-->  2 已支付   （冻结：不可改、不可取消）
    1 已下单/待付款  --取消------>  3 已取消

每个写操作都遵循同一个模板（这是本项目最重要的并发套路）：
    with order_lock(order_id):              # 1. Redis 锁：同一订单串行化
        with db.engine.begin() as conn:     # 2. 一个事务里"读 + 判断 + 条件 UPDATE"
            SELECT ... FOR UPDATE           # 3. 行锁兜底（防锁过期/多实例）
            UPDATE ... WHERE order_status = 旧状态
        if result.rowcount == 0:            # 4. 谁改到了谁赢，输的一方报"状态已变化"
            raise OrderError('STATE_CHANGED', ...)
"""
import logging
import uuid
from datetime import datetime
from decimal import Decimal

from sqlalchemy import text

from utils import db
from utils.lock import LockBusyError, order_lock

logger = logging.getLogger(__name__)

# 订单状态（与 schema.sql 的 1/2/3 一致）
ORDER_UNPAID, ORDER_PAID, ORDER_CANCELLED = 1, 2, 3

MAX_QUANTITY = 999


class OrderError(Exception):
    """业务规则不满足。views 层把它转成 flash 提示 / JSON 错误。"""

    def __init__(self, code, msg):
        super().__init__(msg)
        self.code = code
        self.msg = msg


def _run_locked(fn):
    """把"等不到锁"翻译成统一的业务错误，views 层不用各自处理 LockBusyError。"""
    try:
        return fn()
    except LockBusyError:
        raise OrderError('LOCK_BUSY', '操作处理中，请稍后重试') from None


def get_order(order_id):
    """只读查询，不加锁（展示用）。"""
    with db.engine.connect() as conn:
        return conn.execute(text(
            'SELECT order_id, transaction_id, customer_id, product_id, '
            '       quantity, ppu, amount, order_status, paid_at '
            'FROM orders WHERE order_id = :oid'), {'oid': order_id}).mappings().first()


def create_order(customer_id, product_id, quantity):
    """客户下单。

    安全点：
      - customer_id 由 views 从 session 传进来，绝不来自表单；
      - 单价只从数据库读，前端传的 ppu/amount 一律忽略；
      - 订单里的 ppu 是快照：商品以后调价，历史订单金额不变。
    """
    try:
        quantity = int(quantity)
    except (TypeError, ValueError):
        raise OrderError('BAD_QUANTITY', '数量必须是 1~999 的整数') from None
    if not 1 <= quantity <= MAX_QUANTITY:
        raise OrderError('BAD_QUANTITY', f'数量必须在 1~{MAX_QUANTITY} 之间')

    with db.engine.begin() as conn:
        product = conn.execute(text(
            'SELECT product_id, ppu, product_status FROM products '
            'WHERE product_id = :pid'), {'pid': product_id}).mappings().first()
        if product is None:
            raise OrderError('PRODUCT_NOT_FOUND', '商品不存在')
        if product['product_status'] != 1:
            raise OrderError('PRODUCT_OFF_SHELF', '商品已下架，无法购买')

        ppu = Decimal(product['ppu'])
        amount = (ppu * quantity).quantize(Decimal('0.01'))
        transaction_id = ('W' + datetime.now().strftime('%Y%m%d%H%M%S')
                          + uuid.uuid4().hex[:6].upper())
        result = conn.execute(text(
            'INSERT INTO orders (transaction_id, order_date, customer_id, product_id, '
            'quantity, ppu, amount, order_status) '
            'VALUES (:tid, CURDATE(), :cid, :pid, :qty, :ppu, :amount, 1)'),
            {'tid': transaction_id, 'cid': customer_id, 'pid': product_id,
             'qty': quantity, 'ppu': ppu, 'amount': amount})

    logger.info('下单成功 order_id=%s transaction_id=%s customer=%s',
                result.lastrowid, transaction_id, customer_id)
    return {'order_id': result.lastrowid, 'transaction_id': transaction_id,
            'amount': amount}


def _load_order_for_update(conn, order_id):
    """订单行锁。和 Redis 锁是两层保险：
    Redis 锁挡住"同一订单并发"；FOR UPDATE 兜住"Redis 掉线/锁过期"的极端情况。"""
    return conn.execute(text(
        'SELECT order_id, customer_id, quantity, ppu, amount, order_status '
        'FROM orders WHERE order_id = :oid FOR UPDATE'), {'oid': order_id}
    ).mappings().first()


def _check_access(order, customer_id, as_staff):
    """归属校验：客户只能碰自己的订单；员工/管理员不限。

    不属于自己的订单返回 NOT_FOUND 而不是 FORBIDDEN：
    避免攻击者用"403/404 的差异"枚举订单 ID。
    """
    if not as_staff and order['customer_id'] != customer_id:
        raise OrderError('ORDER_NOT_FOUND', '订单不存在')


def update_quantity(order_id, quantity, customer_id=None, as_staff=False):
    """修改未支付订单的数量。金额用订单里的 ppu 快照重算，不用商品当前价。"""
    try:
        quantity = int(quantity)
    except (TypeError, ValueError):
        raise OrderError('BAD_QUANTITY', '数量必须是 1~999 的整数') from None
    if not 1 <= quantity <= MAX_QUANTITY:
        raise OrderError('BAD_QUANTITY', f'数量必须在 1~{MAX_QUANTITY} 之间')

    def _do():
        with order_lock(order_id):
            with db.engine.begin() as conn:
                order = _load_order_for_update(conn, order_id)
                if order is None:
                    raise OrderError('ORDER_NOT_FOUND', '订单不存在')
                _check_access(order, customer_id, as_staff)
                if order['order_status'] == ORDER_PAID:
                    raise OrderError('ALREADY_PAID', '订单已支付，不能修改')
                if order['order_status'] != ORDER_UNPAID:
                    raise OrderError('ORDER_CLOSED', '订单已取消，不能修改')

                amount = (Decimal(order['ppu']) * quantity).quantize(Decimal('0.01'))
                result = conn.execute(text(
                    'UPDATE orders SET quantity = :qty, amount = :amount '
                    'WHERE order_id = :oid AND order_status = 1'),
                    {'qty': quantity, 'amount': amount, 'oid': order_id})
            if result.rowcount == 0:
                raise OrderError('STATE_CHANGED', '订单状态已变化，请刷新后重试')
            return {'order_id': order_id, 'quantity': quantity, 'amount': amount}

    return _run_locked(_do)


def cancel_order(order_id, customer_id=None, as_staff=False):
    """取消未支付订单（软删除：只把 order_status 改成 3，不删行）。"""
    def _do():
        with order_lock(order_id):
            with db.engine.begin() as conn:
                order = _load_order_for_update(conn, order_id)
                if order is None:
                    raise OrderError('ORDER_NOT_FOUND', '订单不存在')
                _check_access(order, customer_id, as_staff)
                if order['order_status'] == ORDER_PAID:
                    raise OrderError('ALREADY_PAID', '订单已支付，请走退款流程')
                if order['order_status'] == ORDER_CANCELLED:
                    raise OrderError('ORDER_CLOSED', '订单已取消')

                result = conn.execute(text(
                    'UPDATE orders SET order_status = 3 '
                    'WHERE order_id = :oid AND order_status = 1'),
                    {'oid': order_id})
            if result.rowcount == 0:
                raise OrderError('STATE_CHANGED', '订单状态已变化，请刷新后重试')
            return {'order_id': order_id, 'cancelled': True}

    return _run_locked(_do)


def confirm_payment(order_id, staff_user_id):
    """员工确认线下收款：1 待付款 → 2 已支付。

    paid_at / paid_by 是审计字段：谁、什么时候确认的收款。
    这是 B 方案的"真实业务动作"——订单状态不再由假网关推进，而是由人确认。
    """
    def _do():
        with order_lock(order_id):
            with db.engine.begin() as conn:
                order = _load_order_for_update(conn, order_id)
                if order is None:
                    raise OrderError('ORDER_NOT_FOUND', '订单不存在')
                if order['order_status'] == ORDER_PAID:
                    raise OrderError('ALREADY_PAID', '订单已支付，请勿重复确认')
                if order['order_status'] != ORDER_UNPAID:
                    raise OrderError('ORDER_CLOSED', '订单已取消，无法确认收款')

                result = conn.execute(text(
                    'UPDATE orders SET order_status = 2, paid_at = NOW(), paid_by = :uid '
                    'WHERE order_id = :oid AND order_status = 1'),
                    {'uid': staff_user_id, 'oid': order_id})
            if result.rowcount == 0:
                raise OrderError('STATE_CHANGED', '订单状态已变化，请刷新后重试')
            return {'order_id': order_id, 'paid': True}

    return _run_locked(_do)
```

### 2.1 这段代码里每个"为什么"

| 设计 | 为什么 |
|---|---|
| 金额一律 `Decimal` | MySQL `DECIMAL` 经 SQLAlchemy 读出来就是 `Decimal`；用 float 会出现 `0.1+0.2 != 0.3` 的金额误差，财务凭证不能有 |
| `orders.ppu` 快照 + 数量乘快照 | 商品调价后，历史订单金额不能跟着变；改数量时也要用快照价，不能偷偷换成当前价（否则"改数量"就变成"按新价重新下单"） |
| `create_order` 不加 Redis 锁 | 它只做 INSERT，没有"读状态再改状态"的竞争；真正的并发保护靠 `transaction_id` 唯一键与数据库事务 |
| 下单不锁商品行、不扣库存 | 本项目的商品没有库存字段，订单也不做库存占用；面试若被问"真实电商怎么做"：`SELECT ... FOR UPDATE` 扣库存或下单预占，超时释放（这是另一条线） |
| 客户查别人订单返回 404 | 防 IDOR 同时防枚举：403 会告诉攻击者"这个 ID 存在"，404 不会 |
| `FOR UPDATE` 和 Redis 锁并存 | Redis 锁是跨进程的第一道；`FOR UPDATE` 是数据库层的最后一道。锁过期、Redis 挂掉时，条件 UPDATE 仍然保证状态只变一次 |
| `rowcount == 0` 就抛 `STATE_CHANGED` | 不信任"我刚才 SELECT 到的状态"，只信任"UPDATE 实际改到了几行" —— 这就是乐观并发控制的核心 |
